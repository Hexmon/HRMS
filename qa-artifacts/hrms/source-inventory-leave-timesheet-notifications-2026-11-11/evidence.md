## Persistence, tests and confidence boundaries

- The holiday collision was source-confirmed in this pass and then **independently reproduced** in a guarded disposable PostgreSQL fixture on 2026-11-11. The [runtime artifact](../holiday-foreign-id-intake-2026-11-11/pending-holiday-foreign-uuid-cases.md) records exact synthetic setup, requests, SQL/outbox observations and fresh-app reload; it does not establish hosted exposure or the unexecuted cases. Actual `/api/v1/holidays/:id` does **not** match `app.ts:244-259`'s `/api/v1/leave-wfh` domain flush prefix; successful PUT takes full fallback (`hrms_backend/src/app.ts:104-130,278-308`; `L/index.ts:4-6`). Full flush runs `flushPlatform` (and outbox) **before** `flushLeaveWfh`, then commits (`hrms_backend/src/platform/postgres-data-store.ts:650-665,3283`). Outbox key `holiday.upserted:<id>:<version>` can dedupe to an existing B event (`L/service.ts:452-457`; `hrms_backend/src/modules/expenses/events.ts:15-19`), but does not block later holiday SQL. SQL unique-tuple conflict, another full-flush error or outbox error would roll back; those branches remain untested.
- The workflow mutation in row 434 uses `timesheets` domain flush (`hrms_backend/src/app.ts:249`; `hrms_backend/src/platform/postgres-data-store.ts:767-769`). It persists all workflow definitions before timesheet actions (`hrms_backend/src/platform/postgres-data-store.ts:4039-4107`); the action's `submission_id = workflow.id` is allowed by the present no-FK action DDL (`hrms_backend/src/db/migrations/0001_initial.sql:632-639`). No role/company ownership column exists on workflow definitions. This supports the source mechanism; no persisted or browser execution was run.
- `L/__tests__/leave-wfh.integration.test.ts:29-260` checks one-company normal leave/WFH flow, manager approval, monitor, holiday Admin write/Employee denial and export. `T/__tests__/timesheets.integration.test.ts:40-361` checks normal submission/queue/analytics and selected role/OCC behavior. `N/__tests__/notifications.integration.test.ts:18-77` checks owned notifications, another user's read denial and stale version. These tests were read, **not run**. They do not provide two-company denial, cross-company UUID collision, Employee workflow mutation denial, multi-instance concurrency, transfer provenance, full-flush failure or browser evidence.
- **High-risk disposition:** row 334 now has a failed isolated SQL denial case; independent QA recommends **P0 tenant write integrity** pending owner triage and links it to TEN-S25-016/025. Row 434 remains a source-confirmed P1 candidate for explicit Employee denial/noninterference cases in TEN-S25-005/015. Row 430 is a direct global selector leak already within those cards.
