## Cross-cutting boundaries

- `hrms_backend/src/plugins/auth.ts:30-101` requires a live session, active user and active membership for these routes **except** `/api/v1/assets/scan/*` (`:69-70`). It resolves a company but does not attach it to asset queries. `/licenses/activate` and `/licenses/validate` omit a route-local actor check, but are still session-protected by this hook; any active authenticated role can call them.
- `hrms_backend/src/modules/assets/policy.ts:5-9` checks AssetManager/Admin role only. `hrms_backend/src/modules/assets/repository.ts:17-55,73-114,153-222` reads global collections by ID or no filter. `hrms_backend/src/db/schema.ts:2128-2295` gives no company owner to the asset, assignment, request, vendor, maintenance, acknowledgement, recovery or license tables. Thus active membership alone cannot prove a resource/related ID is in the actor's company. `service.ts:611-637` also joins users, assignment, acknowledgements and maintenance globally in its presenter.
- Successful mutation routes flush `assets` in `onSend` (`hrms_backend/src/app.ts:104-129,245-303`). `hrms_backend/src/platform/postgres-data-store.ts:726-801` wraps `flushAssets` and outbox in one SQL transaction, but `:3756-4011` iterates whole shared in-memory asset collections and upserts by global ID; updates are not SQL version-conditional or company-conditional. A failed flush can leave the pre-commit memory changed, and a stale replica can overwrite another committed row. This maps to TEN-S25-001/018. The ongoing asset PR must be reconciled separately and cannot be assumed to fix every route, writer or consumer.
- `hrms_backend/src/modules/assets/__tests__/assets.integration.test.ts:19-95,154-352` has seeded happy-path QR/recovery/license/request/vendor/maintenance tests. It does not demonstrate two-company denial, arbitrary-role termination denial, SQL concurrency/rollback, or public capability rotation. No tests were run here.
