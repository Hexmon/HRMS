## Shared isolated fixture and evidence standard

Use only an authorized isolated PostgreSQL/object-store environment with two fresh API instances and real frontend API mode. Create unrelated companies **A** and **B** with separate Admin, HR, Auditor, Finance and employee identities. Give A and B distinct employee, department, expense, attendance, asset/maintenance/recovery, helpdesk, leave/balance/holiday, timesheet/project-segment and report markers, plus formula-looking text. Deliberately reuse one status, category, department label, employee name and project code across tenants to prove ownership rather than label matching. Record fixture row IDs, ownership columns, counts, hours and expected aggregates by independent SQL before requests. Include an A employee who later transfers to B; keep original-company payroll/audit rows under A. Use non-sensitive synthetic values. Capture HTTP status/body, durable SQL rows/event state, object key/bytes, and browser download bytes. Parse CSV and XLSX with an independent reader and open representative files in **Microsoft Excel and Google Sheets** to confirm formula-looking text remains literal. A response metadata `download_url`, object stat, or MIME alone is insufficient. Do not infer an expected total from the same report function under test.
