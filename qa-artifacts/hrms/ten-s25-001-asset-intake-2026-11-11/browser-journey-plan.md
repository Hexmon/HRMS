# TEN-S25-001/018 real-browser asset journeys — planned, not run

Independent QA source intake at asset branch parent `deb6012d`, 2026-11-11, updated for the uncommitted transaction implementation. This is a test plan, **not** a browser result or case pass. Use a dedicated disposable local PostgreSQL database and Valkey, two API instances sharing only those services and JWT configuration, synthetic Asset Manager/Employee sessions, and a Playwright frontend with `VITE_API_ENABLED=true`, `VITE_API_MOCK_FALLBACK=false`, and local `E2E_API_BASE_URL`. Do not reset the shared test database while either API is live. Capture UI, network status and command key, direct SQL, and fresh-second-instance reads. No hosted environment is authorized for this plan.

For each journey, disconnect before send and verify no SQL effect. For ambiguous response loss, let the server commit through Playwright `route.fetch()`, then abort delivery with `route.abort()`. Retry with the **same** `Idempotency-Key` and request body and verify one durable effect and the original authorized result. Refresh/Back must reconstruct committed state without a false success toast. Do not automate the abort/retry case until stable client intent-key behavior exists.

Current-source caveats to resolve or link as separate tasks: the new intent-key adapter and pending/close behavior require real browser validation; the API does not persist handover/return dates, condition or remarks, so the API-backed assign/return dialogs now hide those inputs; the inventory provider fetches only the first 100 assets; `hr_admin` sees Inventory/Returns tabs but the provider/backend inventory path admits only Asset Manager/Admin. Asset tables still lack company ownership, so `/assets/my` and asset detail can expose historical old-company assignments after transfer; TEN-S25-010/016/017 must settle this before SaaS release.
