## Mechanisms, failure sequences, and limits

1. **Foreign document read or mutation.** Given independently authenticated company A and B actors and a company B document ID, a company A Admin passes `documents/policy.ts:9-12`; a company A Auditor passes read/audit at `:13-15`; HR may access restricted material at `:22-24`; Finance/Director/AssetManager may access nonrestricted material at `:28-32`. `documents/repository.ts:16-30` looks up globally. The GET/download/content/verify/delete paths above have no document-company or business-object authorization. In this checkout, Auditor is **read/audit only**, contrary to older broad wording that implied Auditor write. No A/B runtime request was made. The database metadata has no company column (`hrms_backend/src/db/schema.ts:2050-2076`). DEC-011 requires employee, assigned HR, and company Admin raw-proof access. This is already assigned to TEN-S25-006/016 and R2-S25-003.
2. **Foreign or unrelated attachment and recovery.** A logged-in actor can select an expense ID for row 207; `documents/service.ts:139-165` writes object bytes before metadata. The route does not authorize the expense parent first. A failed relation or later metadata commit may leave an orphan object; a successful relation can contaminate an unrelated ticket. The latter needs an actual isolated API/SQL test, and no hosted R2/Cloudinary behavior is inferred. `documents/service.ts:303-307,:341-374` also deletes bytes before metadata/related links, while protecting live EMS letters/policies at `:322-339`. Existing TEN-S25-007/021/022 covers both.
3. **Foreign EMS queue and decision.** With company A/B records in one store, A HR/Admin can list B profile changes, service requests, onboarding/exit checklists, and probation through rows 228, 232, 234, 236, 238. A role holder can submit B IDs on rows 229, 233, 235, 237, 239. `ems/policy.ts:5-40` checks role/self or assigned approver, not company; repository lookups and `ems/service.ts:640-645` omit company. Stale-version, state and self-decision checks are real mitigations but cannot replace tenant authorization. EMS-S25-001/002 and TEN-S25-016 already own this. The proposed A/B denial test must assert **no change to B profile, letter, checklist/probation state, audit/outbox or linked documents**.
4. **Unverified linked documents and completion.** Rows 230 and 235 accept IDs/flags without checking authoritative proof ownership and verification (`ems/service.ts:193-204,:311-332`). A malicious or mistaken same-company user can link an unrelated document; HR can set onboarding complete with bare booleans. Source proves absence of validation here, not an executed activation bypass; activation is a separate path. Existing TEN-S25-003/006/016 and BIZ-S25-021 cover DEC-007/029.
5. **Current test gap.** `hrms_backend/src/modules/documents/__tests__/documents.integration.test.ts:18,65,185,243` and `hrms_backend/src/modules/ems/__tests__/ems.integration.test.ts:18,139,244,347` cover selected roles/uploads and single-company journeys. This pass did not find two independent company HR/Admin actors, cross-company IDs, assigned-HR proof access, reference deletion under failure, or evidence-backed checklist completion in those integration cases. Tests were not rerun. Resource ownership/backfill and exact assigned-HR representation remain implementation dependencies; no new decision or separate P0/P1 ticket was established.
