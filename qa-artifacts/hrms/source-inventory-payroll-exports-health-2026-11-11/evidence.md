## Failure sequences, task ownership and unknowns

1. **Cross-company HR export (existing P0 mapping).** Put independent A and B users in the loaded store. Authenticate A HR/Admin/Auditor; request `POST /api/v1/reports/exports` with `report_type: "hr/employees"`. The route validates A's membership, then `ReportService.hrEmployees` filters only deleted/status/date/department (`reports/service.ts:372-398`), not A's company; generated bytes and outbox event are created from those rows (`:846-884`). This is a source-confirmed leak mechanism, not an executed A/B request. TEN-S25-008 already owns all report/export company scope. The export metadata GET guard does not repair the bytes generated by the wrong report query. Verify CSV and XLSX contents, document access, creator/Admin/Auditor visibility, denied B ID, original-company history, and no object/event success after failure.
2. **Payroll lock and overlap.** The payroll-period ID boundary has exact company predicates in SQL (`payroll-period-service.ts:388-410`) and transactional advisory locking (`:106-110,:148-150,:225-227`). The lock snapshots available daily records (`:158-181`) without an explicit unresolved *genuine* leave/WFH and worked-time conflict check. DEC-022 treats valid WFH punches as normal work; TEN-S25-027/BIZ-S25-003/DEC-Q09 own genuine-conflict resolution and lock policy. Do not infer final pay or actual overlap occurrence from this source alone. Summary returns full rows (`:270-325`); TEN-S25-029 requires measured size and pagination/streaming design.
3. **Export render/commit failure.** Attendance and report exports render/put objects before `app.ts:onSend` flushes a successful mutation (`app.ts:104-130`; `generated-exports.ts:49-117`). A later DB rejection/crash or retry can leave bytes without a committed job or create duplicate logical work. This is already registered under TEN-S25-021/R2 storage consistency; provider and failure outcomes were not executed here. `reports/service.ts:1089-1134` also defaults unknown report types to expense register, already EXPORT-S25-001; that fallback alone does not establish cross-role disclosure.
4. **Public health disclosure (existing hardening).** Either URL variant is unauthenticated and returns environment/build/dependency diagnostics (`health/routes.ts:7-37`). `health/service.ts:22-44` caches readiness and `:105-111` redacts obvious connection strings and long tokens; those controls do not change the public field set. OPS-S25-001 already calls for minimal public 200/503 output and protected operator detail. No credential leak or exploit was established.
5. **Existing tests and remaining QA.** `attendance/__tests__/attendance.integration.test.ts:303-556,1425-1459` exercises period lifecycle and exports; `attendance/__tests__/regularization-normalized-items.integration.test.ts:634-1003` exercises late correction/snapshot behavior. `reports/__tests__/reports.integration.test.ts:376-486` tests generated CSV/XLSX and a same-Admin company-preference switch, but not independent A/B employee export bytes. `health/__tests__/health.unit.test.ts:6-27` tests readiness caching, while `__tests__/contracts.contract.test.ts:1170-1188,1378-1450` asserts public health contract/rate-limit exemption. These suites were inspected, not rerun; provider, separate company roles, attendance overlap and production-sized responses remain open.

**Disposition:** 12 selected unreviewed API rows traced; one high-risk source-confirmed export mechanism, already registered as TEN-S25-008, and zero distinct unregistered P0/P1 findings. The inventory CSV and all application code remain unchanged.
