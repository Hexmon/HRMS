## Failure sequences, qualifications and QA limits

1. **Cross-company read and state change.** With independent A/B companies loaded, A Admin/Auditor can read B ticket ID, lists and report aggregates through rows 257–258, 262, 264–265, 271–272, 393–401. A FinanceManager/Admin can submit bills on B's known ticket via row 268 if its state permits; A Admin can create/revoke B manager backup assignments via rows 274–275. The source lacks a comparison to captured ticket company or participant company at those paths. This is a high-risk existing TEN-S25-007/008/016/005 mechanism, not an executed A/B result. The exact denied response must leave B state, audit, outbox, payment and notifications unchanged. Self-processing checks and expected-version/state checks are real mitigations where cited; they are not tenant predicates.
2. **Finance amount/reconciliation.** `E/service.ts:1330-1382` records `input.amount` as paid without a purpose-specific positive/bounded rule; `:1417-1496` settles against advance/estimate rather than net paid. This is already FIN-S25-001/BIZ-S25-016 under DEC-024 and pending DEC-BQ09. A signed money type is not universally invalid for a reversal; define operation-specific signs, disbursement caps, adjustments and actuals. No real money transfer or accounting execution was made.
3. **Approver and backup lifecycle.** `E/policy.ts:10-48` checks assigned actor ID and self-processing, but not a current role/company grant on each approval; a removed-role actor who remains assigned is a **conditional authorization question** until assignment semantics and auth-role revocation are tested. `E/service.ts:349-591` and `:1525-1568` use global fallback/backup participants, which BIZ-S25-015/TEN-S25-005/016 own. A/B and role-removal tests must distinguish allowed assignment-based Manager authority from stale Finance privilege; no separate P0/P1 is registered by this static pass.
4. **Scope and persistence limits.** Ticket creation captures company in JSON, not an immutable typed owner column (`db/schema.ts:1869-1906`), and global number generation (`E/repository.ts:20-22`) is not company-scoped. Lists sort/filter hydrated arrays before slicing; TEN-S25-029 covers measured per-company bounds. Existing `expense.integration.test.ts:18-528` covers one-company route/state/self-processing flows, and `reports.integration.test.ts:34-166,167-319` tests selected reports and centrally scoped `/reports/audit`; no independent A/B expense action/report matrix or payment-race/failure injection was established in this tranche. Tests were inspected, not rerun.

**Disposition:** 33 selected API inventory rows traced. Multiple high-risk company-scope and finance mechanisms are source-confirmed and already registered in Sprint 25; **zero distinct unregistered P0/P1**. Inventory CSV, tracker, application code and hosted state remain unchanged.
