# TEN-S25-008 Report And Export Tenant Boundary

## Objective And Success Criteria

- Scope report rows, totals, facets and generated bytes to the authenticated company; preserve DEC-004 original-company history.
- Keep ambiguous source ownership fail closed. Do not claim completion from a metadata-only filter.

## Scope

- Report selectors, export creation, document download and affected frontend controls.
- Separate dependent tasks own source-domain ownership backfills, object lifecycle, stale sessions and scale.

## Evidence And Decisions

- Source at `eb6e94a8` has global HR, expense, leave/WFH, timesheet, asset, project and helpdesk report paths. Export creation reuses them and runs before a full-domain response flush. Report document access is also not tenant-scoped. Reverify exact paths before editing.
- TEN-S25-008 is P0, 8 draft SP, Anurag Kumar. S25-027-U/P/N/F full local cases are at `qa-artifacts/hrms/ten-s25-008-report-intake-2026-11-11/pending-report-export-cases.md`, all Not Tested and unpublished.
- An independent A/B pre-fix runtime probe was rejected by automatic safety review as possible cybersecurity risk. Do not retry through an alternate tool or agent; no exploit execution is claimed.
- DEC-004 preserves original-company historical payroll/audit ownership. DEC-Q03 leaves detailed historical role access and retention unresolved.
- Owner decision for this task: current authorized HR/Admin/Auditor at the original company may read that company's historical reports after employee transfer. One CSV/Excel export is limited to 10,000 rows and 12 calendar months; over-limit input or results must return an explicit error without truncation. This does not assign company ownership to historical source rows that lack it.
- The export request contract requires both `date_from` and `date_to` ISO dates; omitted dates do not mean all history. Microsoft Excel and Google Sheets are the owner's acceptance applications for CSV/XLSX. Opening generated files in both remains pending; serializer assertions alone are partial.
- DEC-051 separately allows current authorized Finance at the original company to view and settle that company's pre-transfer expense ticket. The expense report path uses the ticket's persisted company; this does not generalize Finance access to other historical report families.
- The settlement half of DEC-051 is not implemented by report read scoping. `ExpenseService.settle` and `assertFinanceActor` currently check the assigned ID and workflow status but do not recheck the actor's current Finance role or original-company ownership from SQL. Treat settlement as a TEN-S25-016/expense-workflow release dependency; S25-027 records only report-read evidence.
- DEC-051's direct expense detail, finance-detail and document routes are also outside the scoped report-read path. Their current-company and current-Finance checks remain SAAS-FIN-012/TEN-S25-007/016 release dependencies along with settlement. A Finance report row does not prove that the direct workflow or underlying document bytes are authorized.
- Independent source intake at `eb6e94a8` confirmed that expense tickets carry a persisted recorded `context_payload.company_id` JSON value, while HR, leave/WFH, timesheet, project, asset, and helpdesk historical rows do not consistently carry a company owner. The expense JSON owner is not DB-enforced immutable; a typed, protected owner and backfill remain TEN-S25-007 work. Current user preferences cannot establish ownership after transfer. Attendance day records have `company_id` and a scoped SQL reader.
- Generated report documents lack a company boundary in document authorization. Export creation writes object bytes before metadata/outbox persistence, and the reports mutation route currently invokes the full-store persistence fallback. A report metadata filter alone cannot secure bytes or durability.
- The shared generator also serves core users, attendance and leave/WFH exports. All SQL-backed callers now fail before object PUT/outbox, so those API/UI exports are temporarily unavailable pending the same R2-S25-001/TEN-S25-006/021 delivery work.
- Attendance and export GETs now obtain actor/role/company and rows from a single request-local `REPEATABLE READ READ ONLY` transaction. The live source still loads all matching expense/outbox/evidence rows before paging; production-size bounds remain TEN-S25-029 and this task is draft.
- A Reviewer/Director without current HR/Admin/Auditor authority receives 409 from an unfiltered or team attendance summary because historical team membership cannot be proved. An explicit own-user query can return only their own current-company day rows; a plain Employee is also limited to their own current-company rows. The service filters persisted `company_id` itself, even with a mixed-company store. Manager team report restoration needs an approved historical hierarchy source. Attendance evidence index uses request-local SQL punches, geo reviews, outbox, mobile warnings and regularizations, but timestamp-to-work-date alignment remains TEN-S25-025/030.
- The configured Cloudinary adapter returns public object URLs and cannot stream persisted bytes through a policy-checking API. The product owner plans full Cloudinary removal before launch. Downloadable exports depend on R2-S25-001 private streaming storage and a bounded materializer, plus TEN-S25-006/020/021 document policy/lifecycle work. Existing public URLs already disclosed cannot be revoked by an API check alone.
- Ordinary document uploads and historical non-export Cloudinary URLs are outside TEN-S25-008. Their public-byte exposure is a P0 release dependency owned by R2-S25-001 and TEN-S25-006/020/021; this branch only denies generated/`*_export` documents and does not claim the general document boundary secure.
- The team-utilization CSV action is removed in API mode because `/team-utilization/summary` still derives visibility from hydrated ProjectsService users and project/segment records without immutable company ownership. Local/demo mode retains the neutralizing CSV serializer. The underlying API and on-screen data remain a P0 TEN-S25-009 project tenant-boundary dependency; this report task does not claim that endpoint safe.
- `/reports/audit` filters outbox events by `payload.company_id`, but the outbox table has no typed immutable company owner. This omits missing/foreign-tagged events, yet does not prove that a present JSON tag matches the underlying business record. Durable company ownership, provenance checks and historical backfill are P0 dependencies on the transaction/source-history work (TEN-S25-001/013); audit completeness and tenant safety are not claimed from this filter alone.
- User approved reviewed executable contracts for nonnumeric workflow, manifest, lockfile, runner and shell paths; numerical changed-line and decision coverage remains required for instrumentable product code and scripts. The QA tooling branch owns that gate change, not this task.

## Source Boundary Matrix

| Surface | Durable company source | Current risk | Initial remedy |
| --- | --- | --- | --- |
| Expense summaries and related approvals, audits, payments, documents | Persisted recorded JSON `expense_tickets.context_payload.company_id`; immutability unproved | Global collections and secondary rows | Fresh SQL actor/company and company-ticket-scoped related rows; typed protected owner remains TEN-S25-007. |
| Attendance summary | `attendance.day_records.company_id` | Scoped record loader exists; actor context and evidence joins need verification | Fresh SQL actor/company and scoped evidence rows. |
| Central `/reports/audit` | Expense ticket company and domain audit company; outbox only has JSON `payload.company_id` | SQL-scoped read context exists, but outbox tag provenance is unproved | Preserve scoped filtering and active-role checks; keep durable outbox owner/backfill as TEN-S25-001/013 blocker. |
| HR, leave/WFH, timesheets, projects, assets, helpdesk summaries | No reliable immutable owner on every primary and secondary row | Foreign rows, totals, facets and historical transfers | Deny report/export access until source-domain ownership migration and backfill are verified. |
| Report export job | Outbox `payload.company_id` | Cached actor and arbitrary export type; full-store flush | Fresh actor/company, whitelist, bounded request-local persistence. |
| Generated export document and actual bytes | No company in document policy | Cross-company role can fetch metadata, URL and content | Persist explicit company and enforce at every document read path, including legacy fail-closed. |

`/reports/exports` must not expose `download_document_id` or ready status until document-byte authorization and durable metadata/outbox are proven together.
