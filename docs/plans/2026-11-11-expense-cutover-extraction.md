### Required Two-Stage Patch Manifest

The clean worktree keeps two reviewable patch sets so authority and command reasoning can be inspected independently. They are **not independently deployable**: migration 0068 fences all expense and reviewer-routing DML, migration 0069 expands the command journal for the complete writer set, and migration 0070 makes reviewer-routing ownership immutable and adds the global replay lookup index. Both stages, all three migrations, their generated contract, and the compatible application binary must be promoted atomically after old writers drain.

1. **Stage 1 review set — authority/read boundary:** final 0068; typed original-company owner/quarantine and repair verifier; expense read/page/report/detail/document metadata/raw policy; DEC-051/052/053; fresh request-local dashboard and relationship-aware bounded notification SQL visibility; frontend read compatibility; authority, migration, receipt-policy, report and tenant regression tests. Requester notifications retain their own historical ticket relationship after transfer, while Manager/Finance notification visibility requires current role, original-company membership and current ticket assignment. Null-owner notifications fail closed. This review set ends at the behavior represented by the expense-specific portions through `6ddd44c3` plus only the expense-report hunks of `6903386f`.
2. **Stage 2 review set — transaction-owned command cutover:** 0069/0070; routing advisory locks; immutable mapping owner and legacy quarantine; transaction-owned reviewer-routing list/create/revoke; create/submit/withdraw/clarification/Manager verify/bills plus existing Finance/payment/settlement durable commands; request-local deltas, audit/outbox/notification atomicity, globally company-bound reviewer-routing create replay, indexed replay journal, frontend stable per-intent keys, bounded sequential manager-backup pagination, notification/full-store flush fencing, tenant-scoped routing outbox keys, concurrency/rollback/replay tests and command OpenAPI updates. Reviewer-routing commands perform a non-locking preliminary Admin check, take the subject-independent shared governance lock in the same global-first order as platform/full-store flush, then lock and revalidate the current Admin identity, preference, roles and active company before any client-selected employee lock or tenant mapping access. Create then locks its requester; revoke tenant-scopes the mapping lookup, locks the resolved requester and re-locks/revalidates the row. This review set corresponds to the task-specific parts of `c44a01bb` and depends on Stage 1.

Shared files (`app.ts`, `data-store.ts`, `postgres-data-store.ts`, expense routes/service/tests and generated contracts) retain a hunk manifest for review, but release tooling must treat the combined tree as one atomic cutover artifact.
