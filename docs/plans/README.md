# Execution Plans

Use an execution plan for multi-step, cross-module, high-risk or multi-session work. Plans keep the objective, decisions, progress, verification and recovery evidence reviewable across humans and coding agents.

- Create `docs/plans/<YYYY-MM-DD>-<short-topic>.md` from `TEMPLATE.md`.
- Keep status and discoveries current while implementing; do not rewrite history to make the plan appear smoother.
- Link approved product/security/architecture decisions instead of inventing expected behavior.
- Mark steps and checks accurately as Pending, In progress, Completed, Blocked, Failed or Not run.
- Preserve useful completed plans as delivery evidence. Remove only temporary plans that contain no lasting decision or evidence.
