# Automated Tests And Independent QA Completion

Owner decision: 2026-11-10. Applies to every feature, defect correction and executable behavior change in backend/frontend/workers, and to the corresponding PR. This is the canonical policy referenced by all agent entrypoints.

## Meaningful Input And Output Contracts

Before implementation, map each changed behavior to a test: actor/role/company, input and preconditions, approved expected return/error, persisted state, emitted audit/outbox and effects that must not occur. Every added or changed executable line must be exercised by meaningful unit tests, with observable assertions covering its behavior. For unavoidable infrastructure/SQL/browser boundaries, extract unit-testable decisions and also run integration/component/browser tests against the actual boundary; a mocked unit test alone does not prove SQL locks, RLS, browser behavior or provider delivery. Record which layer exercises each boundary line rather than mislabelling integration coverage as unit coverage.

Require **100% coverage of added/modified executable lines** for the task and a complete inventory of changed decision branches, with allowed and rejected paths tested. Include newly added files and compare against the actual PR base/head. Also report branch coverage and test every changed business/security decision branch; line coverage alone is insufficient. Do not write one trivial test per line, assert implementation details, weaken assertions, skip failing tests or add coverage-ignore directives to meet a percentage. Types, comments, generated outputs and docs are non-executable; explicitly classify them with rationale. Unreachable/dead code should be removed/refactored. An untested reachable line prevents Done; an exception needs an explicit owner decision and cannot be presented as full coverage.

A test uses Arrange/Act/Assert, deterministic synthetic fixtures and an independent expected result grounded in approved rules. Assert errors and forbidden side effects as well as success. Partition inputs into normal, missing/null/empty, invalid, boundary, forbidden role/company/related IDs, stale version/session, transition, duplicate/reordered, concurrency, clock/office/calendar and dependency-failure cases as applicable. Use property/invariant tests for broad input spaces. No finite suite proves every possible input, so retain an explicit risk/coverage gap list.

## Modular Test Placement

Use existing backend Vitest suffixes and domain-local tests. Keep policy/service unit tests separate from SQL/Valkey integration, contract tests and worker/provider adapters. Add a regression reproducer for a bug; show it fails before the fix and passes afterward when a reliable seam exists. Do not substitute broad HTTP scripts for browser role journeys. Frontend business logic, API adapters and components need unit/component tests plus Playwright user journeys for affected behavior. Share fixtures/helpers without creating a monolithic catch-all test script. Existing full-package checks remain required by the verification matrix.

QA-S25-003 adds backend/frontend unit coverage commands, frontend component tests and a PR changed-line/branch gate; see [changed coverage gate](changed-coverage-gate.md) for commands, scope, exclusions and fresh-report requirements. The gate is one numerical prerequisite, not proof of meaningful assertions, integration/browser boundaries or independent QA. Record exact results at the submitted head; a draft or unmerged tooling branch does not establish the gate for another checkout.

## Independent QA Review

Before declaring a feature complete, request a separate QA reviewer/subagent when delegation is available and authorized. Use the [QA specialist](../../.agents/specialists/qa-reviewer.md). Give the reviewer the ticket, approved requirements, base/head diff, real test commands/reports and isolated environment; ask it to derive missing cases from requirements and source instead of merely repeating the implementation author's claims. The reviewer checks test oracles, assertions, uncovered lines/branches, tenant/role boundaries, concurrency/recovery and affected browser journeys. Record reviewer identity, reviewed SHA, findings, disposition, commands run and residual gaps. Fix findings and repeat only affected checks.

An agent review is independent from the implementation pass, not external penetration certification or human UAT. Respect a conversation's no-delegation restriction. If a separate reviewer cannot run, prepare the evidence for an independent human reviewer and leave QA pending; do not call self-review independent or silently approve. Documentation-only tasks receive link/path, consistency and workflow validation and separate review as available; do not invent runtime unit tests for prose. Tests and attacks run only against authorized isolated environments. The planning-only qa-master-checklist supplies test design, never execution permission.

## PR Evidence And Done Gate

Every behavior PR records ticket IDs/owner, approved rule references, source base/head, reproduction, exact commands/environment, meaningful input/output test map, unit and branch reports, changed-line numerator/denominator (or uncovered line list), real DB/worker/browser results where relevant, reviewer identity and findings, migration/rollback, and sanitized artifact links. All results are Passed/Failed/Blocked/Not run with dates. Screenshots, existing tests, a successful build, a narrative review or 100% line coverage alone are not sufficient proof. Use the [PR template](../../.github/pull_request_template.md) and [handoff](../process/developer-handoff-template.md).

Done requires implementation + approved oracles + meaningful tests + full changed-line coverage + changed decision-branch checks + applicable integration/browser gates + independent review with blockers resolved. Never mark the sheet Done or submit a ready-for-merge claim while a required gate is missing. Prepare the PR body and evidence during the task; push/create/submit only when authorized. A submitted draft PR is not Done and a passing local gate is not production readiness.

## Case Design And Sprint Traceability

Standing owner instruction, 2026-11-11: this workflow applies across all sprints to every new feature, behavior update and bug fix. Discuss concrete test cases and expected outcomes while refining requirements, then publish full case bodies with the task in the shared sheet under [task-tracker rules](../process/task-tracker.md). Case titles or repository-only links are insufficient. Provisional cases retain unresolved owner questions; missing approved expectations prevent Ready, and missing required execution/review prevents Done. Discussion does not itself authorize implementation or test execution.

Use the [per-feature case workflow](../../.agents/skills/qa-master-checklist/references/feature-case-workflow.md) before implementation and reconcile it against the final diff afterward. Each behavior task carries stable case/task IDs, independent oracle/source, actor/company/state, applicable input boundaries, concrete actions, expected visible/durable results, forbidden effects, layer and owner. Every changed decision branch needs an explicit mapped outcome; a single partition charter or fixed number of generated cases is not completed branch coverage. Update cases when source, approved rules or discovered failure mechanisms change.

Execute meaningful unit tests and all applicable integration/component/browser cases after each authorized feature slice; retain actual commands, revision and evidence. Planning artifacts use the existing strict **Not Tested** status, equivalent to **Not run** in PR reports. Never turn it into Passed without execution. Record unresolved oracles as NEEDS_BUSINESS_CONFIRMATION and blockers with their owner. Preserve task estimates, parent rollups and historical execution when adding a shared case view. Independent review and all existing completion requirements still apply.

[Testing-skill research](testing-skills-research-2026-11-11.md) explains external tool fit; no external helper was installed. QA-S25-003 still owns missing coverage/frontend unit/CI machinery.
