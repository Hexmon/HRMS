## Engineering Decision

Recommend a **document subsystem redesign inside the existing modular monolith**, with targeted changes in each consuming feature. Keep Render as the API authority and Neon as the durable business authority; use private R2 for bytes. Reuse bounded background infrastructure for cleanup after implementing an explicit media-job handler. An SDK/provider swap alone leaves authorization, response-selected persistence, retries and deletion failures intact. A new standalone media microservice is not justified by measured load or the present scope.

| Option | Assessment |
| --- | --- |
| Replace Cloudinary calls with R2 calls only | Small code change but retains every company/link/persistence flaw and unsafe ordering. Insufficient. |
| Shared document lifecycle and SQL writers, private R2, targeted feature integration | Recommended: one policy/lifecycle, short DB transactions, durable recovery and bounded resource use; preserves module organization. |
| Separate media service or mandatory Worker gateway for all bytes | Additional deployment/auth/observability boundaries; defer until measurements justify moving traffic. A Worker is useful for bounded cleanup or optional future byte delivery. |

## Proposed Durable Model And Boundaries

Names are design suggestions, not migrated tables. Extend documents with immutable `company_id`, owner/purpose, current version/state, optimistic version and retention/hold references; store object versions separately with provider/bucket/key, server-measured length, detected MIME and actual SHA-256. Keep uploader and historical company ownership even after transfer/deactivation. Uploaded originals and safe derivatives are distinct immutable objects when both are required. R2 ETag is not the application's SHA-256.

Add durable upload intents with company/request idempotency key, request fingerprint, opaque object/version IDs, state, lease/attempt deadline and expiry. Conflicting payload under the same request key is rejected. Link records must be company-checked and version-specific when used for proof/approval evidence. Preserve the repository prohibition on cross-schema SQL FKs: use same-schema constraints and scoped cross-domain transaction/validated trigger patterns allowed by the existing gate. A polymorphic type/UUID alone cannot enforce parent integrity.

Move persistence to document command/repository methods with explicit SQL write sets; routes only parse/validate, services/policies authorize and choose transitions, repositories write, and the storage adapter handles streaming SDK operations/errors. Each command commits document/version/pointer/link/audit and required outbox rows together. Do not rely on response serialization or a later whole-domain flush. Remove the exact migrated routes from generic flushing to avoid a second stale write; test remaining legacy writers cannot restore tombstones or old pointers. Load authorization/resource state from durable scoped queries across API instances.

## Proposed Upload, Replacement, Read And Delete Flows

1. **Upload:** authenticate, authorize target/purpose, enforce tenant byte reservation and idempotency; commit a short-lived pending intent. Stream bounded bytes to a private opaque immutable key while measuring size/hash and detecting content; abort/reject early on limits. Use bounded temporary storage and a sandbox when inspection cannot stream. Keep untrusted bytes quarantined until the required checks pass. Finalize active metadata, links, versions, audit and outbox in a short DB transaction using the intent's current state/version. Never hold a DB transaction open during external upload/scan.
2. **Uncertain outcome:** a PUT timeout is not proof no object exists. Reconcile the known intent/key after the upload lease/deadline, verify observed bytes and safely finalize or schedule deletion. Use create-once/conditional writes where supported and verify checksum before retry adoption. Recheck failed and expired intents in bounded batches; account for a late PUT completing after cleanup. An application-level DB state gate must stop cleanup and finalization from both winning. No ordinary request performs a bucket-wide listing.
3. **Replacement:** create a new immutable candidate; the DB transaction swaps the active pointer only if its expected version still matches and records old/new states. Old bytes stay until commit and retention-aware cleanup. Bind proof verification/activation to the exact active version; a new upload does not inherit verification from the previous bytes. Preserve employee/HR-visible replacement history.
4. **Read:** API checks current company, linked target, purpose, role/assigned HR, active state and holds/access policy; log the decision durably. Stream private bytes with safe content type, `nosniff`, `no-store` and attachment disposition by default; only safe image derivatives are inline. Metadata DTOs contain document IDs and allowed business fields, not provider URLs or credentials. An in-progress download cannot retract bytes already delivered; the guarantee is denial of subsequent unauthorized requests.
5. **Optional direct delivery:** short presigned URLs reduce API byte traffic, but possession grants access until expiry. Use only after explicitly accepting that revocation window for that document class. Direct browser PUT is an optimization requiring an upload intent, exact origin CORS, server-controlled key/type, post-upload actual-byte validation and quarantine/finalize. CORS and declared Content-Type are not authorization or content validation. Sensitive proofs default to the authenticated gateway proposal pending final product decision.
6. **Delete:** commit a tombstone/access denial, immutable audit and purge intent first. Bounded cleanup claims an eligible version, checks no active reference/hold and prevents concurrent activation, then deletes only its known object key. Missing object is success; permission/provider failure is retryable/observable. Commit purge completion, retry/DLQ failures and reconcile crashes. Do not delete historical evidence merely because an employee is inactive; undecided retention keeps permanent purge disabled.

## R2 And Resource Choices

- One private bucket per environment with public `r2.dev` and public custom-domain delivery disabled for sensitive files. Bucket-scoped R2 S3 credentials on Render; R2 binding for a Cloudflare cleanup Worker if provisioned. Separate public media only if explicitly approved; never mix proofs and public logo policy by filename or extension.
- R2 guarantees strong object read/write/delete consistency, but cannot make an R2 operation atomic with Neon, retract signed URLs, or invalidate an independent CDN/browser cache automatically. Use immutable version keys and do not cache protected content publicly.
- Existing limits are 10 MiB media and 2 MiB logo/photo by default. Initial single PUT is adequate. Stream with backpressure; bound tenant/global active uploads, bytes, multipart fields/parts, duration, decoded image pixels and export range/rows. Server validation must hold when the browser preprocessing is bypassed.
- R2 does not supply the current Cloudinary transformations by itself. Compare one-time server-side normalized thumbnails with Cloudflare Images binding from private R2 bytes. Decide face-aware cropping explicitly before replacing `g_face`. Avoid repeated transformation per view; cap derivatives/parameters. Malware scanning/provider, permitted formats and parser sandbox budget need a recorded choice; do not call compression an antivirus check. Preserve original evidence if required rather than destructively compressing proofs by default.
- For large exports, commit a job intent, read authorized rows with bounded SQL cursors, stream to storage and atomically publish result metadata. Record progress/failure/expiry; retries do not publish another logical artifact. Small synchronous exports require an explicit measured cap. Include CSV neutralization under TEN-S25-008.
- Neon holds durable state/quotas; Redis may enforce short abuse counters or cache non-sensitive metadata with bounded TTL and tenant/version keys. Do not store file bodies or rely on Redis for document ownership/purge correctness. Cleanup jobs need explicit handlers; merely publishing a document event is not a cleanup implementation.
- Measure baseline and candidate RSS/CPU, peak concurrent uploads, API p95/p99, SQL queries/pool wait/locks, Redis commands, R2 operations/bytes, scan time, queue age/retries/DLQ and export interference with attendance. Current code holds at least the input buffer plus a full-size upload byte copy, before further overhead; this is a source memory mechanism, not a measured RSS value. No user count, throughput or savings is promised without an approved workload and isolated measurements.
- APAC location hints are best effort and do not guarantee India-only storage. Confirm any client residency commitment before provisioning. Retention, recovery objectives and scanner/processing spend remain explicit decisions.

## Required Failure And User Acceptance Matrix

| Scenario | Required observable result |
| --- | --- |
| R2 succeeds, final Neon transaction fails; retry from another API instance | No active document/link/event exposed prematurely; same idempotency key converges to one result or explicit recoverable failure. |
| Intent commits, R2 rejects/times out or request disconnects | Bounded request, durable retry/expiry state and reserved-byte release/reconciliation; no provider body/secret leaked. |
| Active version changes during upload/finalize/delete/activation | One expected-version transition wins; old proof cannot satisfy current verification; cleanup cannot delete the winning active object. |
| Receipt/Admin-logo/export/EMS replacement followed by process restart | Metadata, active pointer, links, versions and required audit/outbox agree in Neon and a second API instance. |
| Purge succeeds then worker crashes; provider denies delete; duplicate queue delivery | Repeated deletion is safe, failures are visible/retryable, and tombstones/history persist. |
| Foreign company IDs, wrong purpose, unassigned HR, Finance/Auditor proof request | Metadata and bytes denied with durable safe audit; document list/export/project wrappers do not leak the ID/name/URL. |
| Spoofed MIME/extension/hash/size, archive bombs, oversized dimensions, many parts | Reject/quarantine within byte/CPU/time/concurrency budgets; browser validation bypass has no security effect. |
| Permission removed, document replaced, browser back/refresh, copied link | Next protected request denied as applicable; no stale public cache, old direct provider URL or misleading expiry promise. |
| Two simultaneous logo/photo replacements or repeated offline upload submission | No deleted current file; conflict/retry shown in UI; durable single logical result with old/new history. |
| Export plus multi-tenant upload burst and cleanup backlog | Record latency/RSS/pool/Redis/R2/queue metrics against approved targets; tenant fairness and attendance behavior measured. No guessed capacity. |
