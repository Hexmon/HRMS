# Projects, Assets And Helpdesk: Source Journey

Snapshot: 2026-11-09 at `af89c6a` plus dirty worktree. The route/auth/service source trace is supplemented by a [synthetic in-memory A/B API probe](../../qa-artifacts/hrms/discovery-2026-11-09/tenant-boundary-probe.evidence.md); this is **not** a browser, PostgreSQL or hosted journey. The target is one company per person at a time, with original-company historical ownership after a transfer (`owner-decisions.md`, DEC-003/004).

## Projects And Capacity

| Step | Current source behavior | Risk or required evidence |
| --- | --- | --- |
| Create / read | `projects/service.ts:createProject` checks the nominated manager is active and in the actor's current company; `listProjects` and `requireVisibleProject` call `canActorSee`. | The project row in `db/schema.ts:projectRecords` has no company ID. `isProjectInActorCompany` infers ownership from the **current** company preference of the manager or any member. The synthetic A/B API probe returned HTTP 200 to B Admin for A's seeded project after the manager preference moved to B. PostgreSQL and authorized transfer remain untested. |
| Roles / write | Portfolio roles may read visible projects; Admin or the project manager may mutate after `requireVisibleProject`. Member/allocation/milestone writes check target users through `requireActiveUser(actor, ...)`; repository versions are compared in process state. | Confirm every nested ID, user and department against the project's immutable company once it exists. A per-process version check is not a cross-instance concurrency condition. |
| Codes / time | `projectRecords.project_code` has a global unique index; `ProjectsService.projectSegments` matches timesheet work by `segment.project_code === project.project_code` across the entire store. | The SaaS target needs a company-scoped code rule and durable project ID on work segments. Otherwise renamed/reused codes or historical transfer can misattribute hours. Current code blocks duplicate active project code globally, so cross-company collision is a schema/scalability issue, not a reproduced present leak. |
| Utilization | `teamUtilizationSummary` first scopes users by current session preference and hierarchy, then sums their work segments and visible projects. Capacity is fixed at 40 hours. | Compare against the approved office working calendar and historical employment/assignment period; test transfer and midweek policy changes. This calculation is a current snapshot, not an immutable payroll record. |

## Assets, Recovery And Public QR

| Step | Current source behavior | Risk or required evidence |
| --- | --- | --- |
| Inventory / assignment | `assets/service.ts:create/list/detail/assign` requires AssetManager or Admin. Repository rows and `db/schema.ts:assetRecords` have no company ID; `assign` accepts an employee ID without a company comparison. | The synthetic A/B API probe returned a seeded asset assigned to A employee E1 in B Asset Manager's HTTP 200 list. Create/assign/return/maintenance/vendor and PostgreSQL tests remain. Preserve original-company asset/recovery ownership after transfer. |
| Requests / recovery | Employee requests are keyed by requester ID; `requestQueue`, `decideRequest`, `recoveryQueue`, `settleRecovery` use role or ID checks without company ownership. The recovery action can change the asset and settlement amount. | Cross-company request and recovery ID tests are launch critical. Also test concurrent settlement and DB-flush failure; these mutations occur in process state. |
| Public scan | `routes.ts` exposes `POST /scan/:qr_hash` without an actor. `createQrHash` combines an asset code with random bytes and hashes it; `scan` returns the QR hash itself, code, type, name, status and assigned/unassigned flag, not employee identity. The client has an `assetsApi.scan` adapter, but source search found no calling page/component. `plugins/rate-limit.ts` has a public-rate bucket for this path. | DEC-016 supersedes the earlier limited-status DEC-014 and approves the present name/type/code/status/assignment-flag exposure. The QR hash echo and rotation/revocation remain open DEC-Q13. Treat the hash as a bearer capability; test lost/shared codes, enumeration, rate limits and the eventual scan UI/printed-label contract. No public-QR abuse was executed. |
| Licenses | Public activate/validate routes search global entitlement and activation arrays; `activateLicense` counts active seats then appends an activation. | Clarify whether licenses are a tenant product surface. Test duplicate/concurrent activation, seat enforcement and response disclosure in an isolated environment before proposing a design change. |

## Helpdesk

| Step | Current source behavior | Risk or required evidence |
| --- | --- | --- |
| Category / create | `helpdesk/categories` has globally unique category keys and no company ID. `createTicket` takes a global category/default assignee and optional related asset/project/document IDs; it does not compare them with actor-company ownership. | A company may get another company's default assignee or link unrelated objects. Confirm desired per-company category/SLA policy and A/B behavior. |
| Read / decisions | `canSeeTicket` permits requester, assignee, any Admin, or a role matching category; `canManageTicket` similarly permits Admin, assignee or category manager. Neither compares company ownership. Tickets in `db/schema.ts` have no company ID. | The synthetic A/B API probe returned HTTP 200 to B Admin for an A-requester ticket after its assignee preference moved to B. Other roles, mutations, SLA report and PostgreSQL need testing. Ensure original company retains historical ownership. |
| Attachments / notes | `addAttachment` and comment creation accept document IDs; `documentFileName` only looks up a matching global document row. `presentTicket` hides internal comments from non-managers. | Authorize each document against the ticket and actor, including raw onboarding proofs. Test requester versus agent visibility, late document deletion, and retry/failed upload. Internal-note hiding does not fix ticket tenancy. |
| SLA / numbering | `SLA_MATRIX` is code-wide; `nextTicketNo` scans the process store and increments a global number. Version comparisons are process-local. | Decide per-company SLA and numbering. Concurrent creates across API instances need a database uniqueness/idempotency test; a single-process unit test cannot certify this. |
