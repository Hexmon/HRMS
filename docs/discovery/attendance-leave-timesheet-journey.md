Snapshot: 2026-11-09, `af89c6a` plus preserved uncommitted work. Classification: static implementation evidence and proposed verification, not a browser result or a confirmed hosted defect. The target SaaS rule is one company per person at a time, with historical records owned by the original company (`owner-decisions.md`, DEC-003/004).

## ATJ-03 — Work Segment To Approved Timesheet

| Link | Current source evidence | Limit / proposed check |
| --- | --- | --- |
| Employee UI | `hrms-client/src/routes/_app/timesheet.index.tsx` sets `readOnly` for pending/approved weeks; `src/lib/timesheets-store.tsx` sends each work segment to the API and submits the cycle separately. | Multi-request save can be interrupted; verify partial save and retry in a permitted browser. |
| API/state | `timesheets/routes.ts` calls `TimesheetService.createSegment/submit/decide`. `submit` requires at least one segment and an inferred manager, snapshots workflow metadata, records an action and emits an outbox event. `decide` checks expected version and current approver/Admin, then records decision/outbox. `state-machine.ts` permits pending → approved/returned/rejected. | Validate double submit, concurrent decisions, failed manager assignment and whether workflow strategy really changes approver choice. |
| Segment integrity | `service.ts:createSegment` checks hours only; `repository.ts:addSegment` overwrites an existing matching segment without checking any pending/approved submission. `presentSubmission` recomputes segments and billable totals from live rows. | **Implementation-vs-intent gap:** DEC-009 requires server-side lock on submission and an approved correction path. An API call may alter approved detail while stored `total_hours` remains the submission snapshot; test with synthetic data. |
| Tenant boundary | `timesheets/repository.ts:findSubmission` finds by ID only; `policy.ts:assertCurrentApprover` permits any Admin role. `service.ts:approverQueue/visibleUserIds/visibleProjects` treat HR/Admin/Auditor as globally privileged and `activeCompany/timesheetPolicy/holidayDates` use first/global data. Timesheet segment/submission tables in `db/schema.ts` lack `company_id`. | **High-risk candidate:** cross-company queue, detail or approval if IDs exist. Trace and test both API visibility and data mutation in a two-company isolated store; current auth checks only the actor's membership. |
