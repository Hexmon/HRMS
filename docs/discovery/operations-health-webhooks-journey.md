# Health, Webhook And Background Operations: Source Journey

Snapshot: 2026-11-09 at `af89c6a` plus dirty worktree. This is checked-in source behavior, not a hosted health or cutover report.

| Boundary | Source path and current behavior | Failure case to verify |
| --- | --- | --- |
| API liveness/readiness | `health/routes.ts` exposes public `/health/live`, `/health/ready` and versioned equivalents. Liveness returns process uptime/version/build SHA. `health/service.ts` checks PostgreSQL table presence, Valkey PING and object-storage `ensureReady`; a failed dependency produces HTTP 503. Results are cached for 30 seconds and concurrent checks share one promise. | A ready result may remain cached during a short outage; check probe interval and recovery under dependency loss. A unit test covers cache reuse, not a real outage. |
| Resend webhook | `webhooks/resend-routes.ts` accepts raw JSON and passes Svix headers to `resend-webhook-service.ts`. The service checks HMAC signature and timestamp tolerance, stores a sanitized provider event, and applies allowed delivery-state transitions. A duplicate event ID returns `duplicate: true` in the process store; PostgreSQL has a provider/event unique index. | Send signed synthetic duplicate and reordered delivery events across two isolated API instances; verify one logical delivery state and no overwritten telemetry after DB commit. Existing webhook unit suite passed 25/25 on 2026-11-09; that is narrower than a two-instance test. Hosted webhook configuration is unverified. |
| Worker cutover | `workers/cloudflare-worker.ts` exposes a public health response with active flag, authenticated signal/lag endpoints, bounded Cron messages and Queue consumers. `wrangler.jsonc` has `WORKER_ACTIVE=false` in checked-in environments; `render.yaml` still declares the legacy polling worker. | Compare actual hosted deployment and queue bindings only in a later authorized operations goal. For local testing, verify inactive Queue retry delay, Cron bounds, duplicate/out-of-order outbox event IDs and DLQ recovery against disposable services. |
| Event semantics | Queue event consumer re-reads a published outbox row and logs its event ID/type. No old Redis Streams business consumer exists per the approved owner answer. | Do not assume UI notification delivery from a published business event. Confirm which user-facing side effects are required by product decisions, then test their real implementation. |

The API liveness and Worker health endpoints intentionally reveal service/build/active metadata. Review disclosure and monitoring needs before changing them; source alone does not establish a security defect. The operational target (latency, availability, queue lag, RTO/RPO, alert ownership) remains unapproved and should not be invented in release criteria.
