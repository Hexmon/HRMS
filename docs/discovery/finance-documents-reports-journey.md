## FDR-01 — Expense Submission To Settlement

| Link | Current source evidence | Limit / proposed check |
| --- | --- | --- |
| UI/API | `hrms-client/src/routes/_app/expenses.create.tsx` and `src/lib/expenses-store.tsx` expose expense create/submit; `hrms_backend/src/modules/expenses/routes.ts` parses create, submit, manager verify, finance approve, payment release, bill and settlement actions. | Browser states, retries and amount presentation remain unexecuted. |
| Ownership and routing | `expenses/service.ts:createTicket` resolves the actor's company and stores it in `context_payload.company_id` on creation. `resolveRoute` requires independent Manager and Finance approvers; an absent approver blocks submission. `policy.ts:assertNoSelfProcessing` blocks requester self-verify, finance approve, payment and close. | Company ID is inside JSON rather than a typed, indexed column in `db/schema.ts:expenseTickets`; test immutability after transfer. | State and audit | `state-machine.ts` defines transitions. `service.ts:managerVerify/financeApprove/releasePayment/settle` check assigned actor and expected version, update status, add approval/payment/audit rows and append outbox events through `writeMutation`. `settle` checks required verified documents and calculates variance with money helpers. | Verify concurrent approvals/payment, duplicate reference, amount limits, event failure/replay and recovery on isolated data. Static code is not a payment or accounting result. |
| Read boundary | `policy.ts:canReadTicket` allows requester/assigned approvers and any Admin or Auditor. `service.ts:getTicket/visibleTickets` use that policy without comparing `context_payload.company_id` to the actor company. `repository.ts:findTicket` is ID-only. | **High-risk candidate:** Admin/Auditor may read another company's ticket if its ID is known or via list. No exploit has been executed. |

## FDR-03 — Reports And Exports

## Decision And Test Seams

- Owner already chose active-company visibility for the central Admin/Auditor audit report; broader tenant-owned data follows the repository invariant in `AGENTS.md`. DEC-011/012 clarify raw onboarding-proof viewers and the expense no-approver block; exact HR assignment and evidence retention remain open.
- Candidate isolated scenarios: company B Admin/Auditor requests company A expense ID, report or document ID; company B employee attaches a document to company A ticket; finance settlement retry and simultaneous payment actions; filename/content mismatch; formula-leading team-utilization name/department and every other reachable CSV/XLSX cell; report export with many rows.
- Existing expense/document/report integration tests are prior implementation evidence only until mapped to these scenarios and executed. The browser origin approval gate is still blocked; no hosted probing is authorized.
