## Mutation And Background Sequence

1. A route validates input, obtains `request.actor`, and calls a domain service. `plugins/auth.ts` rejects missing/revoked sessions, inactive employment, invalid role selection and missing/inactive company assignment.
2. Most non-attendance services mutate the process store and append audit/outbox records. `app.ts:onSend` selects an auth, bootstrap, domain or full persistence flush after a successful mutation. `PostgresPersistence.flushDomain` opens a PostgreSQL transaction and calls domain upsert methods, then commits. Some attendance commands own a direct SQL transaction and are excluded from the flush path.
3. After a successful PostgreSQL mutation, `app.ts` makes a best-effort authenticated outbox signal if configured. A one-minute Cron is designed to recover missed signals. `cloudflare-jobs.ts:drainOutbox` locks at most 50 due rows, enqueues durable event IDs, updates status/retry/dead-letter, and schedules continuation when the batch is full.
4. The event Queue consumer re-reads the PostgreSQL outbox event. Source comments state that no business-event consumer existed for the old Redis Streams; the current Queue handler logs event identity and does not invent a notification side effect. Attendance and location cleanup jobs process bounded batches and enqueue continuation jobs.

## Failure Model And Architecture Decisions To Prepare

| Failure boundary | Source-backed concern | User-visible risk / proposed isolated evidence |
| --- | --- | --- |
| Two API instances | `createPostgresDataStore` reloads rows into a per-process store at startup; `app.ts:onSend` later flushes domain state. `flushAssets` and `flushExpenses`, for example, iterate process-local rows and `ON CONFLICT` upsert without a database version predicate. No ordinary request-time `reload()` call was found in `src/app.ts`. | **Reproduced for assets** with two isolated API instances: A's successful assignment persisted at version 2, then B's unrelated asset create flushed its stale version 1 over it while the assignment row remained. See [executed evidence](../../qa-artifacts/hrms/discovery-2026-11-09/multi-instance-asset-probe.evidence.md). Other domains and hosted topology remain untested. |
| Memory mutation before DB commit | Service methods can change process state before `onSend` begins a flush transaction. The flush can roll back on DB error while process arrays remain changed. | Test a forced DB failure and subsequent same-process read/retry. Confirm HTTP status, database truth, process state and outbox consistency; no failure-injection result exists yet. |
| Outbox send versus commit | `drainOutbox` sends to Queue before its transaction commits. The code explicitly notes that a commit failure after Queue acceptance may duplicate an event ID. | Deduplicate by immutable event ID; verify duplicate, retry and DLQ behavior in local Queue integration, then reconcile lag. Existing worker tests are narrower evidence until executed for this scenario. |
| Clock and historical ownership | `sweepAttendance` scans open historical sessions in bounded cursor order, including inactive/soft-deleted users; `autoCheckoutOpenSession` uses the original company/session policy. | Verify original-company payroll record under transfer/deactivation and worker retry. Existing code aligns with an owner-approved rule, but hosted scheduling and lag remain unverified. |
| Tenant read boundaries | The active-company session preference is mutable and several leave, timesheet, expense, document, project, asset, helpdesk and report paths do not compare historical owner company. See the focused journeys under `docs/discovery/`. | A narrow synthetic in-memory Fastify A/B API probe reproduced asset-list, helpdesk-detail and project-detail boundary gaps. PostgreSQL, browser, full role/route matrix and original-company access after an authorized transfer remain unverified; see `qa-artifacts/hrms/discovery-2026-11-09/tenant-boundary-probe.evidence.md`. |
| Company control plane | Admin security, workflow, email-template, notification-channel, RBAC and finance-governance records are globally stored. Auth password/session checks and the pre-auth rate limiter consume the global security record; email delivery consumes global templates. | A synthetic sequential B-to-A Admin API probe reproduced a globally shared password-minimum change; see [executed evidence](../../qa-artifacts/hrms/discovery-2026-11-09/admin-settings-cross-company-probe.evidence.md). Independent Admin accounts, PostgreSQL, and the operational effect of workflow/channel settings remain unverified. DEC-013 requires company-specific controls with platform defaults. |
| File storage partial commit | `DocumentService.upload` puts object bytes before metadata is flushed, and expense attachment relation is added later. | Simulate metadata/relationship failure with synthetic object storage and confirm orphan cleanup and retry behavior. No observed recovery result yet. |

Design work should address immutable company/office ownership, request-scoped DB transactions, explicit concurrency conditions, rollback of process state, and authoritative report queries. Those are proposals for a subsequent implementation goal. DEC-003/004/008/011 in `docs/discovery/owner-decisions.md` supply the approved SaaS constraints; exact transfer/retention and exception details remain open.
